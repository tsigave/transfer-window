# alpha-v0.5「舰队公司」Checklist

## 版本目标

把单船经营扩展为地月火多船公司：船位、维护、合同、融资和延误在数月尺度互相影响；同时建立可保存、可审计的研发图谱与许可基础。

**前置依赖：** alpha-v0.4 退出条件全部通过。
**退出产物：** 舰队时间轴、火星市场、长期合同、贷款保险、AI多月规划和研发框架。

## 工作流 A：地月火舰队调度

- [ ] 开放火星表面聚合市场、火星轨道及必要中转服务，设置库存、产消和通信延迟。
- [ ] 实现舰队总览、单船时间轴、未来船位、合同承诺、维护窗口和资源预订。
- [ ] 允许同一公司安排多艘船并检测货物、泊位、工质和维护容量冲突。
- [ ] 延误按后续计划、窗口和资源预订传播，提供受影响任务列表及重排候选。
- [ ] 实现公司级储备策略和航迹安全规则，自动标出不符合项但不改写底层物理。

## 工作流 B：合同与金融

- [ ] 实现按期/按量交付的长期运输合同、最低运力、阶梯价格、展期和终止条款。
- [ ] 实现贷款、租赁、利息、抵押、契约指标和还款计划；所有现金流进入账本。
- [ ] 实现基础保险：承保对象、保费、免赔、除外责任、理赔证据和赔付上限。
- [ ] 计算航次、航线、舰船和公司层面的现金流、资本占用与风险调整收益。
- [ ] 财务压力事件不直接没收资产，必须通过逾期、谈判、重组和处置状态推进。

## 工作流 C：研发图谱基础

- [ ] 实现七方向 `TechnologyNode` 图谱、依赖、成熟度和可解锁成果引用。
- [ ] 实现成熟节点的 `Theory`、`Engineering` 项目阶段，消耗人员、设施预算、资金和时间。
- [ ] 实现 `TechnologyLicense` 的范围、期限、签约费、版税与有效状态。
- [ ] 提供初始商业技术、至少每方向三层的占位图谱，并运行拓扑及可达性检查。
- [ ] 研发完成只生成知识、设计或许可权，不自动升级已制造资产。
- [ ] 建立项目与许可UI：依赖、投入、预计时间、权利与不可开始原因可展开。

## 工作流 D：AI多月规划

- [ ] 实现 `StrategicPlan` 最小版，按季度选择市场、现金安全线和舰队方向。
- [ ] 实现 `FleetPlan`，在 3–24 个月内组合去程/返程、维护和合同承诺。
- [ ] AI能够比较租赁、购买、订船和继续使用现有舰船，并通过相同融资命令执行。
- [ ] AI能够竞标长期合同、安排维护、应对延误和调整区域运力。
- [ ] AI能够在自研和购买成熟许可之间做初步比较，不读取隐藏技术结果。

## 接口与存档变更

- 新增 `FleetPlan`、`StrategicPlan`、长期合同、贷款、租赁、保险和资产抵押对象。
- 新增 `TechnologyNode`、`ResearchProject` 和 `TechnologyLicense`。
- 存档加入多船资源预订、延误依赖、财务计划和研发状态；迁移后旧存档获得基础商业技术许可。

## 自动验证

- [ ] `cargo run -p sim-tools -- scenario run earth-mars-fleet --years 3` 完成多船循环且无预订冲突。
- [ ] `cargo run -p sim-tools -- research graph-audit` 无意外环、孤立商业节点或无效成果引用。
- [ ] 延误注入测试能识别并重排所有受影响的后续航段，不修改已执行历史。
- [ ] 贷款、租赁、保险和长期合同通过账本守恒及重复命令测试。
- [ ] AI多月基准在交付率与风险调整收益上优于单合同贪心基线。

## 人工验收剧本

1. 将三艘船安排到地月和地火合同，确认未来船位与维护不冲突。
2. 注入一艘地火船延误，重排下一窗口并查看罚金和后续影响。
3. 用贷款或租赁扩充舰队，签署长期火星合同并查看偿付计划。
4. 启动一个成熟研发项目、购买另一项许可，确认均不会自动改变现役舰船。

## 不纳入本版本

- 玩家自建基地、实验室、实物原型和认证。
- 完整舰船模块设计与自有船厂。
- 谷神星商业开发。

## 退出条件

- [ ] 玩家和AI均能稳定经营多船地月火网络。
- [ ] 船位、维护、资金和合同依赖能解释延误传播。
- [ ] 研发图谱与许可可创建、推进、保存和审计。
- [ ] 自动与人工验收全部通过。

## 变更记录

- 初版：把研发框架放入舰队公司阶段，先支持成熟工程与许可。
