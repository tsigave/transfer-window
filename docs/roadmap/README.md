## 2. Checklist 使用规则

- 每项任务必须同时满足描述中的产物和验证证据才能标记完成。
- 验证证据可以是自动测试名、测试报告、录屏、性能报告或带种子的可重放存档。
- 工作流完成不代表版本完成；版本还必须通过端到端验收与退出条件。
- 若任务被拆分，父项只在所有子项完成后勾选。
- 延后任务必须移动到明确版本并更新双方文档，不能直接删除。

## 3. 共同完成定义

每个版本必须满足：

- [ ] 版本承诺的玩家路径可从全新标准存档完成。
- [ ] 新增数据有模式校验、单位说明、默认值和错误提示。
- [ ] 新增世界变更只能通过应用命令，资金和物资可审计。
- [ ] 自动测试覆盖正常路径、边界、失败和保存载入。
- [ ] 固定种子在暂停、不同倍率和跳时下得到相同状态哈希。
- [ ] 所有迁移在前一版本代表存档上通过，并生成迁移前备份。
- [ ] 性能没有超出该版本预算，或有被批准并记录的回归原因。
- [ ] UI显示单位、数据时刻、状态和不可执行原因。
- [ ] 专题规格、版本索引和变更记录已同步。
- [ ] 没有阻断级缺陷，已知非阻断问题已登记到后续版本。

## 4. 预期验证命令

项目骨架建立后，版本文档统一引用以下命令；实际脚本名若调整，须全局更新：

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run lint
npm run test
npm run build
npm run docs:check
```

场景与性能验证通过 `cargo run -p sim-tools -- ...` 提供稳定入口；每份版本 checklist 给出预期子命令。工具未实现前，对应任务不得勾选。

## 5. 跨版本硬约束

- `alpha-v0.1` 起太阳系主要天体全部存在。
- `alpha-v0.2` 起所有登记天体均可尝试规划航迹。
- `alpha-v0.8` 起木星系统允许商业开发。
- `alpha-v1.0` 包含科技研发、六家公平AI公司和稳定木星供应链。
- Alpha 路线不安排持久多人、网络同步或服务器运维交付。
