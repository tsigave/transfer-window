# alpha-v1.0「行星际承运商」Checklist

## 版本目标

交付完整单机经营产品：太阳系主要天体从开局存在，地月、火星、谷神星和木星系统可开发；真实航迹、市场、舰队、基础设施、工程研发和六家公平AI公司形成长期闭环。

**前置依赖：** alpha-v0.9 退出条件全部通过。
**退出产物：** 签收构建、兼容存档、完整标准战役、发行说明和已知问题清单。

## 工作流 A：范围与数据签收

- [ ] 审计太阳、八大行星、主要矮行星、关键卫星和代表性小天体均存在、可查询并可规划。
- [ ] 审计地月、火星、谷神星、代表性小行星和木星系统的商业权限与服务符合基础设定。
- [ ] 验证未开放天体不会提供市场、补给、维修或建设，但仍允许观测、经过和无人任务。
- [ ] 冻结标准剧本、货物、舰船、设施、技术和AI内容包版本及校验和。
- [ ] 检查所有公开UI、存档与诊断都显示产品版本、内容版本和数据质量。

## 工作流 B：核心闭环签收

- [ ] 从地月单船开局完成合同、航迹、补给、交付、维护和财务循环。
- [ ] 扩展为地月火多船公司，完成长期合同、融资、保险和延误重排。
- [ ] 建设并运营仓储、补给、维修、采集、加工、能源和科研设施。
- [ ] 完成至少一条中级研发路线，经原型、测试、认证、制造与安装投入运营。
- [ ] 设计专业舰船并通过船厂排期、材料、许可和试航进入舰队。
- [ ] 建立谷神星中转和木卫四商业节点，连续运营两个木星供应周期。

## 工作流 C：AI竞争签收

- [ ] 六家主要公司均使用同一应用命令、账本、库存、物理、研发和维护规则。
- [ ] 知识视图测试证明AI无未来信息或玩家私有计划访问。
- [ ] AI能竞标、调度多船、融资订船、建设设施、研发/许可技术和开发木星。
- [ ] 十年多种子仿真中多数AI维持经营，并持续产生合同、产能、资源和技术竞争。
- [ ] 玩家能够从公开市场、订单、船位和施工信号推断AI行为，关键结果有解释记录。

## 工作流 D：质量与发行签收

- [ ] 所有版本共同完成定义、自动测试、性能预算和迁移夹具通过。
- [ ] 标准战役在支持硬件从新建到完成无阻断缺陷，崩溃后可恢复。
- [ ] 教程、键盘操作、缩放、色觉与动效设置完成最终人工检查。
- [ ] 安装包、更新路径、存档位置、备份恢复和诊断导出文档完成。
- [ ] 发行说明列出已实现范围、明确不纳入内容、已知问题和存档兼容承诺。
- [ ] 对根设计原则进行回归评审：所有可玩结果仍能从统一物理与经济状态追溯。

## 接口与存档变更

- 不接受未经迁移的破坏性接口变更。
- 将 alpha-v1.0 存档模式和内容包标记为兼容基线；后续版本必须能识别并迁移。
- 对外只承诺保存文件、内容数据和诊断导出；内部Rust接口仍可在迁移与测试保护下演进。

## 自动验证

- [ ] `cargo run -p sim-tools -- release audit alpha-v1.0` 汇总天体、经济、研发、AI和存档硬约束。
- [ ] `cargo run -p sim-tools -- campaign e2e default-2160` 自动完成代表性全战役。
- [ ] `cargo run -p sim-tools -- ai benchmark --seeds 500 --years 10` 达到批准的公平、压力和生存指标。
- [ ] `cargo run -p sim-tools -- perf alpha-v1-target` 无未批准回归。
- [ ] 桌面端安装、首次启动、升级、存档恢复和卸载测试全部通过。

## 人工验收剧本

使用全新用户配置完成标准战役：

1. 完成地月首单并保持偿付。
2. 扩展到火星、建立多船调度并处理延误。
3. 建设设施、完成中级散热研发路线并制造专业舰船。
4. 在AI竞争下开发谷神星和木卫四。
5. 连续两个木星补给周期维持偿付和有效服务，触发战役完成。
6. 载入中途与完成存档，核对账本、技术、AI和航迹状态。

## 不纳入本版本

- 土星、天王星、海王星和柯伊伯带的完整商业开发。
- FTL、程序化恒星系和恒星际飞行。
- 战术战斗、手动驾驶、逐居民模拟和持久多人。

## 退出条件

- [ ] 所有签收工作流、自动验证和完整人工战役通过。
- [ ] 木星作为可开发气态巨行星系统已进入正式产品闭环。
- [ ] AI公司和研发系统在十年模拟及玩家战役中持续有效。
- [ ] 签收构建、内容校验和、迁移基线、发行说明和已知问题已归档。

## 变更记录

- 初版：定义首个完整单机产品出口，不把路线数字当作完成证据。
