# alpha-v0.3「第一批货物」Checklist

## 版本目标

交付地月单船经营闭环：玩家能接受合同、购买补给、配载、规划航行、交付结算、维护并继续经营，也可能因错误决策进入重组或失败。

**前置依赖：** alpha-v0.2 退出条件全部通过。
**退出产物：** 标准开局、地月节点、货物库存、合同、财务账本、基础维护和公司状态。

## 工作流 A：剧本与经济节点

- [ ] 建立 `scenario/default-2160` 数据包，定义玩家现金、授信、租赁货船、服务权限和地月初始库存。
- [ ] 建立地球地表聚合市场、低/高地球轨道、月面工业区和月球轨道节点。
- [ ] 定义首批货物的质量、体积、储存、品质、损耗和危险属性；聚变燃料与推进工质分开。
- [ ] 实现节点仓储、泊位、装卸和补给容量，任何移动生成 `InventoryMovement`。
- [ ] 验证初始化后各节点和公司资产负债平衡，数据包错误有字段级提示。

## 工作流 B：合同与配载

- [ ] 定义 `Contract` 的货物、数量、节点、时间窗、品质、付款与违约条款。
- [ ] 生成可重复的地月现货合同板，固定种子得到相同合同集合。
- [ ] 实现接受、拒绝、到期和取消状态，重复命令不得重复占用货物或信用。
- [ ] 实现配载计划，校验质量、体积、危险品、储存和合同货物归属。
- [ ] 装卸消耗节点能力与游戏时间，不允许瞬时或跨节点转移。

## 工作流 C：财务、补给与维护

- [ ] 建立双向财务账本，覆盖合同收入、货款、工质、泊位、租金、维护、利息和罚金。
- [ ] 实现购买推进工质、聚变燃料和基础耗材，库存与现金在一个事务内变化。
- [ ] 根据航行累计状态生成基础维护需求、时长和材料成本；过期维护影响可用性而非随机爆炸。
- [ ] 实现信用额度、最低还款、应急授信、资产处置和破产重组的最小状态机。
- [ ] 提供航次损益与现金流页面，任意汇总数字可下钻到账本原因。

## 工作流 D：端到端经营体验

- [ ] 建立“合同→配载→航迹→补给→出发→抵达→卸载→结算”引导流程。
- [ ] 计划界面同时显示合同时间窗、工质储备、费用、预计利润和维护影响。
- [ ] 抵达事件只改变舰船位置与状态；卸载后才转移货物并触发结算。
- [ ] 违约、货损、迟到、燃料不足和泊位满载均提供可解释结果及恢复路径。
- [ ] 保存载入覆盖装载中、航行中、等待泊位和结算前状态。

## 接口与存档变更

- 新增 `EconomyNode`、`CommodityStack`、`Contract`、`Company`、`LedgerEntry`、`InventoryMovement` 和 `MaintenanceTask`。
- 新增 `AcceptContract`、`LoadCargo`、`BuySupplies`、`ScheduleMaintenance` 等命令。
- 存档迁移加入经济节点、合同、账本、库存和公司财务。

## 自动验证

- [ ] `cargo run -p sim-tools -- audit scenario default-2160` 的资金、物资和所有权检查通过。
- [ ] `cargo run -p sim-tools -- scenario run first-cargo` 自动完成一轮地月合同且账本平衡。
- [ ] 属性测试覆盖负库存、重复结算、超载、违约和维护超期。
- [ ] 相同航次在不同时间倍率及中途保存载入后，交付、消耗和财务哈希一致。

## 人工验收剧本

1. 从标准开局选择一份地月合同，比较至少三个航迹并完成补给和配载。
2. 推进至月球、卸载和结算，核对收入、支出、工质、货物和维护状态。
3. 完成返程合同，使公司可继续经营第三个航次。
4. 另建存档故意超支与违约，确认进入应急授信/重组而非无提示卡死。

## 不纳入本版本

- 动态生产消费价格和外部AI公司。
- 多舰队调度、保险、订船与长期合同。
- 火星商业市场和玩家自建设施。

## 退出条件

- [ ] 单船地月循环可连续完成三次，无资金或库存来源不明。
- [ ] 盈利、亏损、违约和破产路径均可复现并解释。
- [ ] 自动测试和人工验收全部通过。
- [ ] 标准开局参数记录为可调基线并附首轮平衡报告。
