# alpha-v1.x「完整外太阳系」Checklist

## 版本目标

在不破坏 alpha-v1.0 存档和经济规则的前提下，按子版本逐步开放土星、天王星、海王星、主要矮行星和柯伊伯带开发。每次开放都必须形成独特且自洽的区域经济，而不是只增加地图图标。

**前置依赖：** alpha-v1.0 退出条件全部通过。
**退出产物：** 外太阳系区域包、人口迁移与灾害传播、区域科研和扩展AI策略。

## 工作流 A：区域开放框架

- [ ] 为每个区域编写资源、交通、环境、人口、基础设施和商业机会说明。
- [ ] 开放权限只修改既有天体的 `DevelopmentStatus`，不替换天体ID或重置历史。
- [ ] 每个区域至少包含进入供应链、当地生产、返程价值和长期维护四类闭环。
- [ ] 区域数据包可独立校验、启用和迁移，缺失内容时存档给出明确错误。
- [ ] 现有导航、自动调度和AI不依赖硬编码的木星终点。

## 工作流 B：土星区域包

- [ ] 开放土卫六、土卫二和土星轨道重点节点，表达大气、挥发物、环系与深空交通差异。
- [ ] 配置适用于低温、远通信和长期可靠性的设施、合同与技术需求。
- [ ] 玩家和AI可以建立木星—土星及内太阳系—土星供应链。
- [ ] 完成区域端到端建设、生产、返程和故障恢复剧本。

## 工作流 C：冰巨星区域包

- [ ] 开放天王星五大卫星、海王星轨道与海卫一的受限商业开发。
- [ ] 引入更长补给周期、弱太阳能、低温材料和极端远距维护约束。
- [ ] 支持区域专用科研、资源与中转设施，并避免复制木星价格结构。
- [ ] AI规划期限与现金模型能够覆盖多年往返，不因短期收益评估放弃全部区域。

## 工作流 D：矮行星与柯伊伯带

- [ ] 逐步开放冥王星系统及其他主要矮行星，代表性小天体沿用区域统计模型。
- [ ] 加入发现、勘探和资源置信度机制，随机改变初始条件而非物理规则。
- [ ] 支持无人前哨、极低吞吐补给、科研和深空中转等专业商业模式。
- [ ] 验证未逐颗模拟的小天体不会凭空产生精确轨迹或无限资源。

## 工作流 E：人口、灾害与科研合作

- [ ] 人口迁移受就业、居住能力、生活成本、安全和交通可达性影响。
- [ ] 灾害使用“强度×暴露×脆弱性”，损失通过供应链和服务能力传播。
- [ ] 增加跨公司科研合作、区域许可和共同基础设施合同，仍使用公平信息边界。
- [ ] 长期仿真验证外太阳系不会因数值源项无限增长或永久停摆。

## 接口与存档变更

- 扩展区域数据包、资源置信度、人口迁移、灾害暴露和合作研究合同。
- 每个 alpha-v1.x 子版本提供从 alpha-v1.0 及前一子版本的迁移。
- 不改变已有天体、公司、技术和账本ID语义。

## 自动验证

- [ ] `cargo run -p sim-tools -- regions audit --all` 检查权限、货流、技术和迁移。
- [ ] 每个区域运行至少二十年多种子经济/AI仿真，记录存活、市场和物流指标。
- [ ] `cargo run -p sim-tools -- save migrate-from alpha-v1.0` 保留原战役资产和历史。
- [ ] 灾害和人口场景通过确定性、守恒与可解释因果检查。

## 人工验收剧本

1. 从一份完成木星开发的 alpha-v1.0 存档升级。
2. 选择一个新区域，完成勘探、首批物流、设施建设和本地产出。
3. 处理远距故障或灾害并恢复供应链。
4. 与AI竞争或合作建立区域业务，确认旧区域继续运行。

## 不纳入本版本

- FTL、其他恒星系和程序化星系生成。
- 把全部真实已知小天体逐颗加入独立模拟。
- 持久多人和服务器功能。

## 退出条件

- [ ] 土星、冰巨星和主要矮行星至少各有一个完整可玩区域包。
- [ ] alpha-v1.0 存档可迁移且原有经营结果保持可解释。
- [ ] 人口、灾害、科研合作与区域AI通过长期仿真。
- [ ] 新区域具有独特物流与工程约束，而非参数换皮。

## 变更记录

- 初版：远期版本按区域包交付，具体子版本在实施前冻结。
