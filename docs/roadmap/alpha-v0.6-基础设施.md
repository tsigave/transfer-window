# alpha-v0.6「基础设施」Checklist

## 版本目标

让公司能够通过真实物流建设仓储、补给、维修、采集、加工和科研设施；研发从抽象项目进入实物原型与试验阶段，AI可参与相同投资。

**前置依赖：** alpha-v0.5 退出条件全部通过。
**退出产物：** 分阶段建设、设施运营、建设物流、实验室、原型和测试证据。

## 工作流 A：设施与建设项目

- [ ] 定义设施蓝图、位置、能力、建材清单、人员、能源、散热、维护与运营成本。
- [ ] 实现选址权限、施工阶段、物资交付、施工设备和设施排期校验。
- [ ] 建设只消耗目标节点实际库存；缺料时暂停并生成可承运需求。
- [ ] 各阶段完成可释放明确的部分能力，拆除或取消需保留已消耗资源和可回收资产记录。
- [ ] 基地页面展示物质、能源、物流、工程、人员和商业能力及瓶颈。

## 工作流 B：首批基础设施

- [ ] 实现仓库、泊位/装卸、工质储罐、燃料站和维修站。
- [ ] 实现水/挥发物采集、基础分离、金属加工和结构件生产线。
- [ ] 实现能源供应、储能和散热能力；产线不能超过可用功率或热预算。
- [ ] 实现设施故障、退化、维护和备件需求，损失由暴露与脆弱性决定。
- [ ] 允许第三方购买明确服务并按容量排队，收入与消耗可审计。

## 工作流 C：实验室、原型和测试

- [ ] 实现 `ResearchFacility` 的设备能力、环境、人员和时段预订。
- [ ] 实现 `PrototypeProgram` 的设计修订、物料清单、制造、运输和资产状态。
- [ ] 实现 `ResearchEvidence` 的来源、条件、质量、适用范围与保密级别。
- [ ] 成熟技术原型按确定规则完成；前沿项目在创建时固定未知阈值和随机流。
- [ ] 失败原型生成预定义证据或次级成果，不允许通过读档刷新结果。
- [ ] 轨道试验必须安排真实运输、试验窗口和遥测回收，缺一则不能进入下一阶段。

## 工作流 D：经济与AI建设行为

- [ ] 设施建设产生公开材料需求、施工合同、泊位使用和可观察进度。
- [ ] AI通过 `InvestmentCandidate` 比较净现值、供应风险、建设排期和退出价值。
- [ ] AI能够建设至少仓储、燃料或维修设施，并安排物资运输及融资。
- [ ] AI能够投资实验室、启动原型或购买许可，并遵守相同设施容量。
- [ ] 多家公司争用同一施工/研究能力时，通过公开排期和合同解决，不能越权占用。

## 接口与存档变更

- 新增设施蓝图、设施实例、建设阶段、能力预订、生产线、能源和维护对象。
- 新增 `ResearchFacility`、`PrototypeProgram`、`ResearchEvidence`、`InvestmentCandidate`。
- 新增 `CommissionFacility`、`BookFacility`、`BuildPrototype`、`RunTest` 等事务命令。

## 自动验证

- [ ] `cargo run -p sim-tools -- infrastructure conservation` 覆盖建设、生产、损耗和拆除的物资/能源守恒。
- [ ] `cargo run -p sim-tools -- scenario run build-fuel-depot` 从运输建材到提供首笔补给服务全程通过。
- [ ] `cargo run -p sim-tools -- research prototype-replay --seeds 100` 验证结果确定、失败有产出且无设施超订。
- [ ] AI建设场景中全部材料、资金、船位与设施时段可追溯。

## 人工验收剧本

1. 在月球节点规划燃料站，运入建材并观察各阶段能力释放。
2. 使用新设施为玩家和AI各完成一次补给，核对库存、容量和收入。
3. 建设实验室并制造散热器原型，运输到轨道完成热循环试验。
4. 故意中断一种材料供应，确认建设/原型暂停且市场产生可解释需求。

## 不纳入本版本

- 完整舰船设计、造船厂和商业认证。
- 谷神星与木星商业建设。
- 巨型城市和逐建筑空间布局。

## 退出条件

- [ ] 建设和原型均由真实物资、能源、人员和设施时段驱动。
- [ ] 至少六类基础设施形成运输—建设—服务闭环。
- [ ] AI可公平建设并与玩家争夺容量。
- [ ] 研发失败确定且有次级产出，自动与人工验收通过。

## 变更记录
