# 游戏基础具体设定

## 1. 产品定位

Solarstorm 是一款建立在统一物理与工程数据上的单机行星际航运及工业经营游戏。玩家不手动驾驶飞船，而是经营公司、规划航次、配置运力、投资设施和研发技术。底层模拟回答“能不能做到”，经营系统回答“值不值得做”。

基础体验目标：

- 玩家能从航迹、货物、现金和设备状态追溯每次盈亏。
- 船只在真实时间和空间中持续存在；当前选择会改变未来船位和机会。
- 太阳系从开局起是完整且连续的世界，开发权限不会决定天体是否存在。
- 复杂计算可以自动化，但玩家始终可以展开数据来源和约束。
- AI公司使用同样的资产、信息、物理和经济规则制造商业压力。

## 2. 标准剧本：2160 年

### 2.1 世界状态

- 商用聚变推进出现约二十年，已可用于大型货船，但反应堆、散热器、工质、维修和寿命成本仍然昂贵。
- 地月空间具有成熟人口、制造、金融和补给网络，是开局最大的需求与资本来源。
- 火星正在快速扩张，依赖高价值设备、人员和生命支持进口，同时出口部分材料、科研与专业产品。
- 谷神星已经出现前哨、采集与转运活动，但尚未形成稳定的大型商业枢纽。
- 木星系统存在科研和政府设施，商业开发尚未规模化；其开发是首个战役阶段的远期机会。
- 其他主要天体均可被观察和抵达，但开局不提供市场、补给或建设许可。

人口、产能、价格和舰船参数属于版本化剧本数据，不写死在模拟代码中。数值平衡以产生稳定开局和可解释供需为准，不宣称是对 2160 年的现实预测。

### 2.2 玩家身份与开局资源

玩家经营一家注册于高地球轨道的独立航运公司。标准开局包含：

- 一艘租赁的中型聚变货船，支持地月运输并可在改装后承担地火任务。
- 约 18 个月基础运营现金，以及规模有限、带偿付约束的授信额度。
- 高地球轨道公共泊位、仓储和维护服务的使用权，不拥有初始基地。
- 地月现货合同市场访问权；火星、谷神星和木星合同随信誉、能力及开发状态开放。
- 已商业化通用技术的使用许可，不拥有独占先进技术。

开局数值需在 `alpha-v0.3` 的标准剧本中冻结；冻结前以 `scenario/default-2160` 数据包中的值为唯一来源。

### 2.3 经营目标与失败

短期目标是完成地月合同并建立现金缓冲；中期目标是形成地月火舰队、研发或引进专业技术并拥有基础设施；长期目标是运营谷神星—木星供应链。

公司在现金耗尽时不立即结束游戏，依次进入应急授信、资产处置和破产重组。只有重组后仍无法维持一艘可运营舰船或履行最低债务安排时，标准战役才判定失败。`alpha-v1.0` 的战役完成条件是连续两个木星运输周期保持偿付能力，并维持至少一个木星系统商业节点的有效服务。

## 3. 太阳系覆盖

### 3.1 初始独立天体目录

从 `alpha-v0.1` 起，以下对象拥有稳定 ID、父天体、物理参数和可查询星历：

- 中心天体：太阳。
- 行星：水星、金星、地球、火星、木星、土星、天王星、海王星。
- 主要矮行星：谷神星、冥王星、阋神星、妊神星、鸟神星。
- 地球与火星卫星：月球、火卫一、火卫二。
- 木星关键卫星：木卫一、木卫二、木卫三、木卫四。
- 土星关键卫星：土卫一、土卫二、土卫三、土卫四、土卫五、土卫六、土卫八。
- 天王星关键卫星：天卫一、天卫二、天卫三、天卫四、天卫五。
- 海王星与冥王星关键卫星：海卫一、冥卫一。
- 代表性小天体：灶神星、智神星、健神星、灵神星、凯龙星、阿罗科特。

小行星带、半人马族和柯伊伯带同时拥有区域统计对象，用于表达未逐颗登记的小天体资源、发现和交通密度。增加代表天体只能扩充数据包，不得改变既有 ID 或存档语义。

### 3.2 天体状态与权限

每个天体分别记录发现状态与开发状态：

- `Observed`：可搜索、查看和查询星历。
- `Surveyable`：可执行遥感、飞掠、环绕和无人采样任务。
- `TransitOnly`：允许载人或货运抵达，但无合法商业服务。
- `CommercialOpen`：允许交易、补给、建设和长期经营。

全部初始目录天体至少为 `Observed`。`alpha-v0.2` 后全部天体可成为航迹目标；是否能安全抵达由舰船与航迹求解决定，而非开发权限。未开放区域不得凭空提供工质、维修、货物或人口。

### 3.3 逐阶段商业范围

- `alpha-v0.3`：地球轨道与月球节点。
- `alpha-v0.5`：完整地月火商业网络。
- `alpha-v0.7`：谷神星和选定代表性小行星。
- `alpha-v0.8`：木星系统；木卫四为主枢纽，木卫三有限开发，木卫一和木卫二以科研及高风险任务为主。
- `alpha-v1.x`：逐步开放土星、天王星、海王星、主要矮行星和柯伊伯带。

气态巨行星本体不使用地表基地模型。木星开发包括轨道设施、卫星基地及后期大气资源采集平台。

## 4. 核心经营循环

1. 阅读市场、合同、预测和竞争情报。
2. 选择合同或自行组织货物，计算货值、时间和违约风险。
3. 为指定舰船比较出发日、航程、载荷、工质、寿命和抵达状态组成的 Pareto 解。
4. 配载、补给、维护并提交航行计划。
5. 推进时间，处理设备退化、延误、价格变化和竞争行为。
6. 抵达、卸载、结算合同与资金，更新舰船状态和公司信誉。
7. 将利润和信息投入舰队、设施、技术、许可或长期供应链。

导航系统默认提供最快、平衡和节能三个代表解，但它们必须来自同一个可行解集合，不得实施隐藏倍率。

## 5. 基础经济对象

### 5.1 货物分类

首批货物至少包括：水、生命支持耗材、食品、推进工质、聚变燃料、结构金属、复合材料、工业机械、电子设备、反应堆组件、医疗品、消费品、科研载荷和乘客。

每类货物定义质量、体积、储存条件、损耗规则、危险级别和品质；价格由本地库存、预期需求、订单簿和可达运力形成。聚变燃料与推进工质始终是两个库存。

### 5.2 经济节点

经济节点挂接在天体表面、轨道或拉格朗日区域，而不是直接等同于天体。节点至少记录人口、库存、产能、消费、泊位、仓储、补给、维修、金融和建设权限。

初期节点包括地球地表聚合市场、低地球轨道、高地球轨道、月球表面工业区、月球轨道、火星表面聚合市场和火星轨道。后续按版本增加谷神星、代表性小行星、木卫四和木星轨道节点。

### 5.3 公司与合同

公司拥有现金、债务、信誉、人员、技术权利、舰船、库存、设施、合同和预测。合同必须指定货物或乘客、数量、装卸节点、时间窗、品质、安全条件、支付与违约方式。任何合同都不能瞬间传送货物或忽略泊位能力。

## 6. 舰船与工程原则

- 设计由反应堆、发动机、工质舱、货仓、结构、散热、屏蔽、自动化、乘员和冗余模块组成。
- 权威结果必须遵守质量流、功率、推力、有效排气速度、热容量、散热和寿命约束。
- 更先进技术通过部件、工艺、软件或许可进入设计，不提供无来源的公司全局百分比加成。
- 航迹执行会积累发动机等效全功率时间、反应堆循环、结构负载和辐射剂量，并影响维护。
- 船厂能力限制最大尺寸、总装质量、特种部件、建造速度与排期。

## 7. 信息与交互层级

- 运营层：合同收益、预计到达、工质、风险和公司规则符合性。
- 规划层：出发日—航程—载荷—成本 Pareto 前沿、船位和维护排期。
- 工程层：状态矢量、推力段、功率/热曲线、质量预算和误差余量。
- 空间层：2D/2.5D 日常地图与按需 3D 轨道分析视图。

所有层级读取同一权威数据。视觉比例放大、局部原点和轨迹采样只影响显示。

## 8. 明确不在 alpha-v1.0 范围

- 持久多人、服务器部署、网络同步和多人时间制度。
- 战术战斗、舰船直接操纵、逐乘员或逐居民模拟。
- 所有已知小天体逐颗建模、所有外行星区域开放建设。
- FTL、程序化恒星系和恒星际航行。
- 完整国家政治、军事冲突或角色扮演叙事系统。
