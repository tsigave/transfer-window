# v0.2 网页前后端分离技术指导

本指导定义 `v0.2.1` 起的正式运行方式。React 与 Rust 服务独立构建和部署；Rust 事实层仍是唯一权威，Tauri 暂停发行。

## 组件与信任边界

```text
浏览器 React/Three.js
        │ HTTPS / JSON / SSE
        ▼
sim-server · /api/v1
        │
        ├── sim-app          世界命令、修订号、确定性事件
        ├── sim-trajectory   权威航迹任务与取消令牌
        ├── sim-engineering  舰船工程约束
        └── sim-save         SQLite 原子存档与迁移备份
```

浏览器可以插值地图视觉状态，但不得生成可提交的航迹、修改世界或直接接触 SQLite。所有写操作由服务端重新验证。当前服务进程持有一个单玩家世界；多账号、共享世界和水平扩展不在 v0.2 范围内。

时间轴可以自由查看星历；“执行至此”才会把当前显示时刻提交给权威事件队列。服务拒绝倒退世界时间，回看历史不会改写舰船、资源或计划。

## 本地运行

安装前端依赖后运行：

```bash
npm install
npm run dev
```

该命令同时启动：

- Rust API：`http://127.0.0.1:3000/api/v1`；
- Vite 网页：`http://localhost:1420`，开发代理把 `/api` 转发到 Rust。

需要单独调试时使用 `npm run dev:server` 与 `npm run dev:web`。停止父进程会同时终止两个开发子进程。

## 配置

| 变量 | 默认值 | 作用 |
| --- | --- | --- |
| `TRANSFER_WINDOW_BIND` | `127.0.0.1:3000` | API 监听地址 |
| `TRANSFER_WINDOW_DATA_DIR` | `var/transfer-window` | SQLite 默认槽目录 |
| `TRANSFER_WINDOW_WEB_ORIGIN` | `http://localhost:1420` | 唯一允许的浏览器 CORS Origin |
| `TRANSFER_WINDOW_ALLOW_REMOTE` | 未设置 | 设为 `1` 后才允许非回环监听 |
| `VITE_API_BASE_URL` | 空，同源 `/api` | 前端生产构建使用的 API 根地址 |

`VITE_API_BASE_URL` 在构建时写入前端资源。推荐生产环境仍使用同源反向代理，把 `/api/*` 转发到 Rust，以减少 CORS 与凭据配置错误。

## API v1 契约

| 方法与路径 | 类型 | 说明 |
| --- | --- | --- |
| `GET /api/v1/health` | 查询 | API 与项目版本健康检查 |
| `GET /api/v1/bodies` | 查询 | 权威天体目录 |
| `GET /api/v1/bodies/{id}/state` | 查询 | 指定 TDB 微秒的状态矢量 |
| `GET /api/v1/map-sample` | 查询 | 同一时刻的全目录状态样本 |
| `GET /api/v1/world` | 查询 | 当前权威快照与世界修订 |
| `POST /api/v1/simulation/advance` | 变更 | 按事件边界推进到指定时刻 |
| `GET/POST /api/v1/saves/default` | 查询/变更 | 载入或原子保存默认槽 |
| `POST /api/v1/trajectory/jobs` | 任务 | 创建 3×5 权威航迹搜索 |
| `GET /api/v1/trajectory/jobs/{id}` | 查询 | 获取进度、结果或结构化失败 |
| `GET /api/v1/trajectory/jobs/{id}/events` | SSE | 推送进度与终止事件 |
| `DELETE /api/v1/trajectory/jobs/{id}` | 变更 | 触发协作式取消 |
| `POST /api/v1/voyages` | 变更 | 重新验证并排期可执行方案 |
| `POST /api/v1/voyages/{id}/cancel` | 变更 | 幂等取消尚未开始的计划 |

航迹 POST 返回 `202 Accepted` 和任务地址。前端同时订阅 SSE 并轮询任务状态：SSE 提供低延迟进度，GET 保证断线恢复，不依赖事件流完整送达。服务最多保留 128 个并发运行任务；达到上限返回 `TOO_MANY_TRAJECTORY_JOBS`，终止任务会在需要空间时清理。

错误响应统一为：

```json
{
  "code": "SOLUTION_INVALIDATED",
  "message": "solution input hash no longer matches the request",
  "fieldPath": null
}
```

前端只把稳定 `code` 用作控制流。重复世界命令必须复用原 `command_id`；使用新 ID 重试代表新的玩家意图。

## 存档与迁移

权威存档位于 `${TRANSFER_WINDOW_DATA_DIR}/alpha-v0.2.transfer-window`。schema 1 SQLite 仍由 `sim-save` 备份为 `.pre-v0.2.bak` 后迁移。旧网页 `localStorage` 只在服务器返回 `SAVE_NOT_FOUND` 时导入一次；正常保存和载入不再写浏览器快照。

不要让多个服务进程共享同一个 SQLite 默认槽，也不要把数据目录放在会进行非原子同步的网络盘。备份时应先停止写入或复制一个已经完成原子替换的槽文件。

## 生产部署与安全

```bash
cargo build -p sim-server --release
npm run build
```

部署 `target/release/sim-server` 与 `dist/`，并由反向代理提供 TLS、静态文件和 `/api` 转发。默认回环限制用于防止误暴露；设置 `TRANSFER_WINDOW_ALLOW_REMOTE=1` 只解除监听保护，不会自动提供身份认证。

当前版本是单租户服务。若对公网开放，反向代理必须至少提供访问认证、TLS、请求体大小限制、速率限制和日志脱敏；在实现服务端用户隔离前，不能让不互相信任的玩家共享同一进程或数据目录。

## 验证

```bash
cargo test -p sim-server
cargo clippy --workspace --all-targets -- -D warnings
npm run test
npm run build
```

服务集成测试覆盖健康检查、权威星历、服务器存档，以及“创建航迹任务—取得执行级方案—排期—推进到抵达”的完整 HTTP 玩家路径。前端测试覆盖 API 存档、旧浏览器视图导入、权威方案展开与排期。
