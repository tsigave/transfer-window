# 科技树与研发系统

## 1. 设计目标

研发是工业与航运的消费者，也是公司差异化的来源。它不能是等待进度条换取全局加成，而应通过人员、设施、能源、材料、原型、任务数据和认证与现有系统连接。

采用混合研发图谱：成熟工程路线的结果和主要成本可预知；前沿路线提供概率区间、可能分支与失败风险。失败必须留下可利用证据或次级成果。

## 2. 七个技术方向

1. 推进：喷管、磁约束、工质注入、推力调节和高功率持续工作。
2. 反应堆与能源：聚变控制、功率转换、储能、配电和安全停堆。
3. 热管理：散热器材料、热泵、相变储热和高温工艺。
4. 材料结构：复合材料、辐射屏蔽、压力容器、疲劳监测和大型结构。
5. 导航自动化：星历、航迹优化、自主故障处理、编队和港口调度。
6. 资源工业：采掘、分离、精炼、挥发物处理、木星大气资源采集。
7. 居住生命支持：闭环生命支持、医疗、旋转居住、辐射防护和长期乘员健康。

技术节点可以跨方向依赖，但必须至少有一条不依赖随机成功的基础商业路线，避免图谱意外死锁。

## 3. 研发生命周期

### 3.1 阶段

- `Theory`：验证原理与依赖，主要消耗科研人员、算力和实验室时间。
- `Engineering`：形成部件与工艺规格，消耗工程人员、材料样品和试验设备。
- `Prototype`：制造一个或多个真实资产，占用船厂或专用设施并消耗库存。
- `Testing`：在地面、轨道或实际任务中产生带条件的证据。
- `Certification`：按用途、工作包线和安全等级批准商业使用。

阶段不可通过单一抽象点数跳过。购买许可可以跳过自行研发，但不绕过本地制造能力、适配测试和许可范围。

### 3.2 成熟与前沿节点

- 成熟节点公开依赖、预算范围、试验要求和成果；投入足够资源后确定成功。
- 前沿节点公开成功区间、关键未知量和潜在分支，但隐藏本局具体阈值。
- 前沿结果由项目创建时的种子、世界技术状态、团队能力和证据决定；保存读档不能刷新结果。
- 追加试验能缩小不确定性、调整原型或安全终止项目，但不能无成本重掷。

### 3.3 失败与次级成果

失败结果至少产生一项：负面证据、改进后的安全限制、材料/传感器/控制工艺、下一原型风险降低或可出售的非核心专利。灾难性失败还会损失原型、设施时间和信誉，但不得删除已获得的科学证据。

## 4. 资源与证据

项目预算包含：资金、研究人员工时、工程人员工时、设施时段、能源、消耗材料、试验资产、运输任务和日历时间。所有实物通过经济节点库存与运输系统交付。

`ResearchEvidence` 至少记录来源、技术方向、测试条件、质量、适用范围和保密级别。证据来源包括：

- 实验室与原型试验。
- 舰船常规运营的可靠性与寿命数据。
- 极限航迹、事故调查和异常恢复。
- 合作研究、公开论文、购买的数据包和竞品分析。

证据只能降低与其测试条件重叠的风险。地月低功率运行数据不能直接认证木星辐射环境下的全功率设备。

## 5. 技术成果进入生产

研发成果以以下对象生效：

- 新舰船或设施部件。
- 现有部件的新修订版与改装包。
- 制造、维护或资源处理工艺。
- 导航、诊断和调度软件。
- 指定用途与工作包线的认证。
- 可出售、购买或限定区域使用的技术许可。

任何成本、质量、寿命或性能变化都绑定具体对象和修订版。已制造资产不会因研究完成自动升级。

## 6. 许可、合作与知识产权

- 自研：成本最高但拥有成果，可自行制造或授权。
- 购买许可：支付签约费与版税，受用途、区域、期限和产量限制。
- 合作研究：按合同分摊投入、证据和权利，合作方违约由合同系统处理。
- 公开产品分析：只能获得公开性能与合法拆解证据，不能直接复制受保护工艺。

AI和玩家使用同一许可市场及合同。技术转让必须生成资金账目与权利记录。

## 7. 数据模型与状态约束

- `TechnologyNode`：方向、依赖、成熟度、可能成果、阶段模板。
- `ResearchProject`：所有者、节点、当前阶段、预算、团队、证据和风险状态。
- `PrototypeProgram`：设计修订、物料清单、设施预订、试验计划和资产状态。
- `Certification`：被认证对象、用途、工作包线、签发方、有效条件。
- `TechnologyLicense`：权利人、被许可人、范围、期限、费用和状态。
- `ResearchFacility`：位置、设备能力、容量、环境和排期。

禁止出现负项目成本、同一设施超额预订、缺少依赖却进入认证、已吊销许可继续新生产等状态。

## 8. 版本落地

- `alpha-v0.5`：图谱、依赖、项目、许可和成熟节点的理论/工程阶段。
- `alpha-v0.6`：实验室、设施排期、实物投入、原型和测试证据。
- `alpha-v0.7`：认证、部件修订、制造工艺、运营数据和 AI 专业化研发。
- `alpha-v0.8`：辐射、深空可靠性和木星资源工业路线。
- `alpha-v0.9`：平衡、不确定性表达、教程和长期仿真。
- `alpha-v2.0`：多条 FTL 理论路线、巨型试验设施和首次可靠飞行。

## 9. alpha-v1.0 最小研发内容

每个方向至少包含一条三层成熟路线和一个前沿节点；总图谱目标为 35–50 个节点。至少提供以下中级路线供战役验收：

`高温散热材料 → 可展开大型散热器 → 深空连续高功率认证`

完成该路线必须制造散热器原型、执行轨道热循环试验、取得指定功率包线认证，并把认证部件安装到一艘新造或改装舰船上。

## 10. 验证清单

- 图谱拓扑排序成功，除明确标记的互斥分支外所有商业节点均可达。
- 固定种子和相同投入产生相同前沿结果，存档重载不改变结果。
- 原型物料、资金、能源和设施时段均真实扣减且可审计。
- 失败产生定义过的证据或次级成果，不出现空白失败。
- 许可过期、撤销、超范围和版税结算均有集成测试。
- 完成技术不会自动修改既有资产；只有制造、安装或软件部署后生效。
- 自动玩家可完成至少一条中级路线，AI也能评估自研与购买许可的差异。
