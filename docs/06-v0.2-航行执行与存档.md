# v0.2 航行执行与存档

alpha-v0.2 的查询与世界变更保持严格分离。`sim-trajectory` 只产生无副作用方案；`sim-app` 是复核、排期、取消和事件执行的唯一写入边界。

## 应用命令

- `QuoteTransfer`：读取当前舰船和蓝图，返回搜索报告，不修改世界；
- `ValidateTransfer`：重新计算输入哈希，并核对舰船、载荷、出发时刻、求解器版本、复核容差和 `Executable` 等级；
- `ScheduleVoyage`：在期望世界修订匹配且复核通过后创建航行计划与事件；
- `CancelPlan`：只允许取消尚未开始的计划，并移除对应未来事件。

变更命令携带稳定 `command_id` 和期望世界修订。同一命令重试返回原收据，不重复创建计划或消耗资源。舰船、载荷或求解输入变化时，排期以 `SOLUTION_INVALIDATED` 失败；失败不修改世界修订、舰船库存或事件队列。

## 确定性事件执行

批准方案按 `due_time`、优先级和稳定事件 ID 拆成推力、滑行、接近与抵达事件。推力事件按各段工作时间占比分配并累计推进工质、聚变燃料、反应堆等效全功率时间和发动机寿命；滑行事件释放热缓冲并重置连续工作计时，但不重置库存或累计寿命。

抵达事件比较实际与批准方案的空间、速度、工质和寿命误差。误差在容差内时计划进入 `Arrived`；超容差时进入 `Diagnostic`，记录结构化诊断并保留实际状态，不把舰船强行吸附到目标。播放倍率只控制调用节奏，不改变事件边界、消耗或最终状态。

## 存档 schema 2

`GameSnapshot` schema 2 新增：

- 带状态矢量和活动计划 ID 的舰船；
- 全部航行计划、执行状态和实际消耗；
- 求解器版本与执行诊断；
- 幂等命令收据和未来航行事件。

载入 schema 1 存档时，迁移器保留原有时间、选中天体、事件与随机流，并加入标准 Lunar Courier 舰船。SQLite 文件在迁移前复制为同路径的 `.pre-v0.2.bak`；浏览器存档写入新的 alpha-v0.2 键并保留旧键作为备份。未知 schema 仍显式返回 `SAVE_UNSUPPORTED`。

存档 JSON 启用浮点往返格式，保证航行中保存载入不会改变求解状态或最终哈希。

## 验证入口

```bash
cargo run -p sim-tools -- replay voyage --rates 1,100,10000
```

该回放从同一地月 `Executable` 方案排期，跨三种倍率推进到抵达，比较最终存档哈希、推进工质和寿命消耗。测试还覆盖旧解安全失效、排期/取消幂等、未来事件移除、超容差诊断、schema 1 备份迁移以及航行中存档往返。
