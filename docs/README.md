## 文档优先级

出现冲突时，按以下顺序处理：

1. 已验收版本的实现和自动化测试代表当前事实。
2. 对应版本 checklist 定义该里程碑的承诺范围。
3. 本目录的专题规格定义跨版本规则。
4. 根目录核心设计总结定义长期设计原则。

任何改变物理规则、经济守恒、AI公平性、研发阶段或版本出口的决定，都必须同步修改专题规格与受影响的版本 checklist。

## 统一约定

- 所有路线版本号均使用 `alpha-` 前缀。
- Checklist 标记：`[ ]` 未完成，`[x]` 已完成；只有附带实现、测试或验收证据时才能勾选。
- “存在”表示天体进入统一目录、星历、地图和存档；“可通航”表示可提交航迹规划；“可开发”表示允许建立经济节点和基础设施。
- 所有影响世界状态的计算由 Rust 模拟核心裁决；界面预览不得直接修改权威状态。
- Alpha 路线仅承诺单机产品，不包含持久多人、网络协议或服务器运维。

## 变更流程

1. 在目标版本文档的“变更记录”中说明原因。
2. 更新接口、数据或玩法专题文档。
3. 为变化增加自动测试或人工验收步骤。
4. 若版本出口改变，同步更新路线总览中的依赖和退出条件。
